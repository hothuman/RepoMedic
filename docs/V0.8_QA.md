# RepoMedic v0.8 — QA / candidate for v0.9

This release stabilizes v0.7. It **does not certify** a scan result as secure or runnable.
The optional Windows builder is a **recipe**, not proof of a tested binary.

## Automated checks

Run from RepoMedic project root (Windows):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q .
.\.venv\Scripts\python.exe cli.py . --format html --output repomedic-smoke.html
```

Expected: 135 tests run, `OK` in the Python 3.13 Linux development environment.
Windows 11/Python 3.15 results are **unverified** until the maintainer runs them.
HTML content is escaped; exported reports can include local paths, filenames and diagnostics and should be reviewed before sharing.

## Manual Windows checks (do not skip before beta)

- [ ] Open app and rescan a Python-only project twice; after scans the tree and score refresh.
- [ ] Scan a Node-only project; no missing Python `.venv` false alarm.
- [ ] Scan a mixed project with valid Dockerfile and Compose; no exceptions.
- [ ] Import a small **public** GitHub repo; then import another and check temporary folders are cleaned after each scan and on app exit.
- [ ] Invalid GitHub URL, offline mode, 404/403, ZIP too big: friendly error, app still works.
- [ ] Export TXT, JSON, HTML; test writing to a non-writable destination; no half-written final file.
- [ ] Scan a project with >400 Python files and nested virtualenv; bounded results, GUI remains responsive.
- [ ] CLI exit status 0, 1, 2 on deliberate test fixtures.
- [ ] Run `python scripts/benchmark_scan.py <folder>` and document times/system specs.
- [ ] If distributing Windows executable, install PyInstaller to `.venv` and run `powershell -ExecutionPolicy Bypass -File scripts/build_windows.ps1`; test `dist\RepoMedic\RepoMedic.exe` and the complete `dist\RepoMedic` folder on a **clean** Windows machine.
- [ ] Verify zip does not ship `.venv`, `report.txt`, `.env`, caches or credentials.

## Limitations

- No Docker/Node/Python scripts or GitHub Actions workflows are executed.
- Docker Compose and GitHub Actions diagnostics are **heuristic text checks**, not YAML interpreters.
- Dependency diagnostics are not an arbitrary dependency solver or package vulnerability scanner.
- An imported ZIP is bounded (25 MiB archive, 100 MiB uncompressed, 4000 entries); ZIP paths violating Windows filesystem rules are rejected.
- The local `.venv` check reads metadata; it does not run the env's Python interpreter.
- Findings/score alone do **not** prove the app is secure, complete or installable.
